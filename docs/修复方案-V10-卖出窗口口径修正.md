## 1. 用户反馈 → 代码根因（已逐条核实，直接采信，不要重新排查）

用户在卖出窗口下拉里看到 9 个持仓**全部**是 `🔴 … · 可卖`，且金额"像翻了十倍"，而其中多个持仓实际处于浮亏。核实结果：

### 根因 A：下拉里的数字是**市值**，却裸显示成 `$332.00`，用户必然读成"价格"

`src/alertRules.ts:35`：
```ts
label: `${symbol} · $${item.marketValue.toFixed(2)} · ${[...item.brokers].sort().join(' / ')}`,
```
`item.marketValue` 是同标的跨券商市值合计（`alertRules.ts:24-27`，期权已乘 contractMultiplier）。数值本身没算错，但一个紧跟代码的裸 `$` 金额，在股票语境下就是"股价"。于是 `NKE · $332.00` 被读成 NKE 股价 332（实际约 66），`MSFT · $25745.19` 更是荒谬 —— 这就是用户说的"翻了十倍的涨幅"。**这是标注缺失，不是计算错误。**

### 根因 B：「可卖」丢掉了量化系统给的全部限定条件

`src/components/ConditionLookup.tsx:317-323`：
```ts
const readyFamily = family && snapshot?.summary?.sell_ready.some((item) => item.symbol === family.family);
return readyFamily ? `🔴 ${fallbackLabel} · 可卖` : `⚪ ${fallbackLabel} · 无`;
```
`QuantSellOpportunity`（`types.ts:280-285`）实际带四个字段：`symbol / trigger / detail / shadow`。上面这段**只用了 symbol**，把 `trigger`（为什么触发）、`detail`（依据数字）、`shadow`（是否仅观察期、未正式生效）全部丢弃，压成两个字"可卖"外加一个红点。

对照 `src/components/OpportunityOverview.tsx:38` 和 `:88` —— 同一份数据在机会一览里是**正确**渲染了 `trigger`、`detail` 和「（观察期）」的。**同一个快照，两个组件表现不一致，卖出窗口这个是漏的。**

### 根因 C：「可卖」这个词本身曲解了量化口径 —— 它与用户的买入成本无关

测试夹具里的真实数据形状（`src/testFixtures/quantAnalysis.ts:193-196`）：
```ts
sell_ready: [{ symbol: 'MSFT', trigger: '知足常乐',
  detail: '自基准日 +18.00% vs QQQ +20.00%', shadow: true }]
```
「知足常乐」比较的是**自反弹基准日以来的涨幅 vs QQQ**，属于相对强弱/机会成本判断。一个深套后从底部反弹 18% 的持仓，完全可以既满足这个条件、又仍然浮亏 30%。而且这条 `shadow: true` —— 观察期，本就不该当作可执行动作展示。网站把它显示成红点「可卖」，等于把"相对跑输 QQQ 的观察项"翻译成了"建议卖出"。**用户的判断是对的：在浮亏持仓上显示"可卖"是错的。**

### 根因 D：卖出窗口全程不显示用户的实际盈亏，尽管数据就在手上

`SellWindow`（`ConditionLookup.tsx:246-291`）展示修复期、知足常乐、补涨收敛、止盈阶梯、近期信号，**唯独没有"这个持仓你现在赚还是亏"**。而成本数据是有的：`snapshot.holding_costs[symbol].weighted_average_cost`（`types.ts:164-169`），`quantSync.ts:167-173` 已把它写进持仓的 `buyPrice`，`App.tsx:221/257` 也已 `applyQuantHoldingCosts`。
更糟的是止盈阶梯（`ConditionLookup.tsx:273-283`）只是罗列"盈利 X%–Y% → 减总仓 Z%"，从不告诉用户当前盈亏落在哪一档、或者根本没到第一档。**红点「可卖」+ 一串减仓阶梯 + 不显示浮亏 = 用户合理地认为系统在叫他割肉。**

### 待取证（不确定，Phase 4 取证后再定责）

9 个标的**全部**亮红点，可能是：①量化系统的 `sell_ready` 确实包含这么多族（属量化侧口径，需转量化侧）；②同族联动放大（MSFT/MSFU 同族、NVDA/NVDL 同族，`held_symbols.includes()` 命中，逻辑上正确但视觉翻倍）；③`held_symbols` 跨族错配（网站匹配 bug）。**本轮先出证据，不猜。**

## 2. 任务

### Phase 1：金额必须标明是「市值」（`alertRules.ts` + 两处下拉）

- `AlertHoldingOption` 增加结构化字段：`marketValue: number`、`brokers: string[]`（label 保留，供既有调用方兼容）。
- label 改为：`${symbol} · 市值 $${marketValue} · ${brokers}`（"市值"二字必须出现）。
- 全仓检查还有哪些地方把市值裸显示成 `$X` 而未标注（`ConditionLookup` 卖出下拉、`AlertRulesPanel`、`OpportunityOverview`），一并补"市值"标注。**不得改动数值计算。**
- 测试：label 含「市值」；金额等于该 symbol 跨券商市值合计；期权按 contractMultiplier 计入。

提交：`fix: label holding amounts as market value`

### Phase 2：卖出状态标签还原量化语义（`ConditionLookup.tsx`）

1. `sellStatusLabel` 重写为纯函数并抽到 `src/sellStatus.ts` 便于测试：
   ```ts
   export type SellState = 'window_open' | 'observation' | 'none';
   export function resolveSellStatus(snapshot, symbol): { state: SellState; trigger?: string; detail?: string }
   ```
   - 在 `sell_ready` 中命中且 `shadow === false` → `window_open`；
   - 命中但 `shadow === true` → `observation`；
   - 未命中 → `none`。
2. 下拉文案（**「可卖」二字禁止再出现**，它读作"该卖"）：
   - `window_open` → `🟠 {label} · 卖出窗口开启`
   - `observation` → `⚪ {label} · 观察期`
   - `none` → `⚪ {label} · 无`
3. 卖出窗口详情区顶部新增「触发依据」卡片：显示 `trigger`、`detail`，`shadow` 时加琥珀色「观察期，未正式生效」，并固定附一句口径说明：
   > 该判定来自量化系统的相对强弱口径（自反弹基准日涨幅 vs QQQ），**与你的买入成本无关**；是否盈利请看下方「本族当前盈亏」。
- 测试：`shadow: true` 时不得出现 🟠 与「卖出窗口开启」、必须出现「观察期」；trigger/detail 出现在详情；全仓 grep 无「可卖」字样。

提交：`fix: preserve quant sell trigger, detail and shadow in ui`

### Phase 3：把用户实际盈亏摆进卖出窗口（追溯用户原话「我有很多还在亏损的状态」）

1. 新纯函数 `src/familyPnl.ts`：
   ```ts
   export function computeFamilyPnl(holdings, family, heldSymbols, holdingCosts):
     { marketValue: number; costBasis: number; pnl: number; pnlPct: number; coverage: 'complete'|'partial'|'unavailable' }
   ```
   - 归族口径复用现有逻辑（family 本身 + `held_symbols` + 期权按 `option.underlying`）；期权市值/成本按 `contractMultiplier`；
   - 成本优先级：`holding.costOverride` → `holding.buyPrice > 0` → `holdingCosts[symbol].weighted_average_cost`；任一持仓取不到成本 → `coverage: 'partial'`；全取不到 → `'unavailable'` 且不输出 pnlPct。
2. `SellWindow` 顶部新增「本族当前盈亏」卡：市值、成本、浮盈亏金额与百分比（红绿），金额走 V4 显示货币层；`coverage !== 'complete'` 时标注「成本数据不完整，盈亏仅供参考」。
3. **浮亏保护**（核心）：`pnlPct < 0` 时，止盈阶梯区整块置灰，并在其上方显示醒目提示：
   > 当前为浮亏 −X%，止盈阶梯（最低档 +Y%）尚未适用。下方阶梯仅作参考，不构成减仓提示。
4. 盈利时的阶梯定位：高亮 `pnlPct` 所落档位；未达第一档则显示「距第一档 +Y% 还差 Z 点」。
- 测试：浮亏族 → 无档位高亮 + 出现「尚未适用」；盈利 25% 且档位 20–30% → 该档高亮；成本缺失 → 出现 coverage 提示且不显示误导性百分比；期权族按乘数计算正确。

提交：`feat: show family pnl and gate profit-taking ladder on losses`

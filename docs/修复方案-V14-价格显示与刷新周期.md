## 1. 根因（已核实，直接采信）

### 问题 A（高）：量化快照**根本没有自动刷新**，只在页面加载时拉一次

`App.tsx:301`：
```ts
useEffect(() => { void refreshQuantAnalysis(); }, [refreshQuantAnalysis]);
```
依赖数组里只有函数本身 —— **没有任何 `setInterval`**。用户不手动点「刷新快照」，数据可以停留几小时不动。

对照：同文件里提醒规则（`ALERT_RULES_REFRESH_MS = 35 分钟`）和行情（`MARKET_SESSION_REFRESH_MINUTES = 35`）都有定时器，**唯独量化快照漏了**。用户看到的「7 分钟前」只是首次加载时刻的静态文案。

### 问题 B（高）：量化快照里**没有任何价格字段**

`types.ts:151-161` 的 `depth_window`：
```ts
depth_window?: {
  applicable: boolean; open: boolean;
  current_pct: number;        // 当前回撤 -21.80%
  threshold_pct: number;      // 阈值 -16.24%
  price_session: string;      // 只有"盘中/夜盘"这种时段标签
  win_rate_60d: number | null; n: number;
  sample_insufficient: boolean; bear_included: boolean;
};
```
全快照检索 price 相关字段：只有 `price_session`（时段标签）和 `triggered_session`，**没有 current_price、没有高点价、没有阈值价**。

所以界面只能显示「当前回撤 21.80% / 阈值 16.24%」，用户无法知道"跌到多少钱才算达标"。**这不是网站丢字段，是契约里就没有** —— 根本解法要量化侧补，见配套需求单。

**但网站侧可以先自行推算**：网站已有自己的行情代理 `/api/quotes`（Yahoo/NASDAQ），能拿到当前价 P。由量化给的回撤百分比可反推：
```
高点 H     = P / (1 + current_pct/100)     // current_pct 为负数，如 -21.80
阈值价 T   = H × (1 + threshold_pct/100)
下一档价   = H × (1 + next_level_pct/100)
```
**注意口径风险**：量化的回撤可能取自夜盘价，网站行情是 Yahoo 延迟价，两者不同源 → 推算出的高点会有偏差。因此推算值**必须标注**，且量化侧补了真字段后要优先用真字段。

### 问题 C（中）：估值分位数据**已经有了，但被藏在折叠块里**

用户截图显示「参考信息（不参与开窗）→ 个股 PE 分位 20.40%」—— 这正是他想要的"当前估值在历史上的哪个位置"，量化系统**已经在算**（`ConditionLookup.tsx:167-180` 的 `ReferenceInfo`，还有 `ndx_percentile`、`soxx_percentile`、`cnn`）。

问题是：①默认折叠，②纯文字一个数字，③没有"这个分位是高是低"的直觉表达。用户想要的是**图 3 那种历史曲线 + 当前位置**。

**Koyfin 调研结论（已查证）**：
- Koyfin **没有公开 API**，官方说明数据商限制其开放 API；
- 唯一途径是 Enterprise 套餐 **$59/月** 才含 API；标准套餐 Plus $39/月、Pro $79/月均无 API；
- **结论：不建议接入 Koyfin**。用户已有的量化系统本来就在算 PE 分位，接一个付费源做重复的事不划算。

**替代方案（推荐）**：量化系统能算出分位，说明它手里有历史 PE 序列。**向量化侧要一个历史 PE 序列的导出**即可画出图 3 那种曲线，零额外成本、口径统一。见配套需求单。网站侧本轮先把已有的分位数字做成可视化。

## 2. 任务

### Phase 1：量化快照定时刷新（纯网站侧，立即可做）

1. `src/quantAnalysis.ts` 新增导出常量：`export const QUANT_ANALYSIS_REFRESH_MS = 25 * 60 * 1000;`（25 分钟，取用户所说 20–30 分钟的中值）。
2. `App.tsx`：为 `refreshQuantAnalysis` 增加 `setInterval`，写法对齐同文件已有的 `ALERT_RULES_REFRESH_MS` 定时器（含 `clearInterval` 清理）。
3. 页面从后台切回前台时补一次刷新：监听 `document.visibilitychange`，`visibilityState === 'visible'` 且距上次刷新 > 5 分钟时触发一次（避免频繁切换时轰炸）。
4. UI：快照时间文案旁固定显示刷新周期，例如 `快照 2026-07-22 12:44 ET，7 分钟前 · 每 25 分钟自动更新`。
5. **测试**：定时器按 25 分钟触发（vi.useFakeTimers）；卸载时清理；可见性恢复且超过 5 分钟才触发（4 分钟时不触发）。

提交：`feat: auto refresh quant snapshot every 25 minutes`

### Phase 2：深度买入窗口显示价格（推算 + 优先真值）

1. 新纯函数 `src/depthPrice.ts`：
   ```ts
   export interface DepthPriceView {
     currentPrice: number | null;   // 来源：量化真字段优先，其次行情代理
     highPrice: number | null;      // 推算：current / (1 + current_pct/100)
     thresholdPrice: number | null; // 推算：high × (1 + threshold_pct/100)
     source: 'quant' | 'derived' | 'unavailable';
   }
   export function buildDepthPriceView(depth, quotePrice, quantPrice?): DepthPriceView
   ```
   - `quantPrice`（量化侧未来补的真字段，见需求单）存在时 `source='quant'`，直接用；
   - 否则用网站行情代理的当前价推算，`source='derived'`；
   - 两者都无 → `unavailable`，UI 只显示百分比（**不得显示假价格**）。
   - 除零保护：`1 + current_pct/100` 接近 0 时返回 null。
2. `ConditionLookup.tsx` 的 `DepthHighlight`：在「当前回撤 / 阈值」两个大数字下方增加一行价格：
   ```
   现价 $384.98 · 高点 ~$492.30 · 阈值价 ~$412.35
   ```
   - `source === 'derived'` 时，高点与阈值价前加 `~` 并附小字：`价格由行情代理现价与量化回撤反推，与量化取价时段（{price_session}）可能有偏差`；
   - `source === 'quant'` 时不加 `~`、不加偏差说明。
3. 数据来源：复用已有的行情代理调用结果（`marketData.ts` 的 quote），**不新增数据源、不新增依赖**。若该标的不在持仓中而无报价，允许显示 `unavailable`。
4. **测试**：`current_pct=-21.80, threshold_pct=-16.24, quotePrice=384.98` → `highPrice≈492.30`、`thresholdPrice≈412.35`（容差 0.01）；`quantPrice` 存在时优先且 `source='quant'`；`current_pct=-100` → 返回 null 不崩溃；无报价 → `unavailable` 且 UI 不出现价格行。

提交：`feat: derive and display depth window prices`

### Phase 3：估值分位可视化（用已有数据，不接外部源）

1. `ReferenceInfo`（`ConditionLookup.tsx:167-180`）从 `<details>` 折叠改为**默认展开的卡片**，标题改为「估值位置（参考，不参与开窗）」。
2. 每个分位数字配一条**水平分位条**（0–100%，纯 CSS/SVG，不引依赖）：
   - 标出当前位置的刻度点与数值；
   - 分位 < 30 标绿（历史偏低）、30–70 中性灰、> 70 标红（历史偏高）；
   - 条下小字注明含义：`分位 20.40% = 当前 PE 低于过去约 80% 的时间`。
3. 个股 PE 分位、纳指100 PE 分位、SOXX 分位、CNN 各一条（沿用现有 `gate.reference_only` 的判断决定显示哪些）。
4. **不得自造分位数字**；字段缺失时该条显示"暂无"。
5. **测试**：分位 20.4 → 绿色档 + 文案正确；分位 85 → 红色档；字段缺失 → 显示"暂无"且不渲染分位条。

提交：`feat: visualize valuation percentiles with position bars`

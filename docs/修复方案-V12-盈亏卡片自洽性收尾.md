## 2. 三项遗留问题与修法

### 问题 A（中）：成本不完整时，卡片三个数字不自洽 —— 用户心算必然对不上

**实证**（诊断脚本已跑通并删除）：正股市值 11,500（成本 11,376.40）+ 2 张期权市值各 2,000（成本未知）：

| 卡片显示 | 数值 |
|---|---|
| 市值 | $15,500（**全族**，含未计成本的期权） |
| 成本 | $11,376.40（**仅已计成本部分**） |
| 浮盈亏 | +$123.60（= 已计成本部分市值 11,500 − 成本 11,376.40） |

用户心算 `15,500 − 11,376.40 = 4,123.60`，与显示的 `123.60` 相差 **$4,000** —— 恰好是两张未计成本期权的市值。断言 `marketValue - costBasis !== pnl` 已通过，确认不自洽。

> 用户上一轮正是因为"数字对不上"才发现 bug 的；这个残留会再次触发同样的不信任。

**修法**：

1. `familyPnl.ts`：`FamilyPnl` 增加 `costedMarketValue: number`（函数内已在算，只是没返回）与 `uncostedMarketValue: number`（= `marketValue - costedMarketValue`）。不改任何既有计算。
2. `ConditionLookup.tsx` 的「本族当前盈亏」卡片：
   - `coverage === 'complete'`：维持现状（三格：市值 / 成本 / 浮盈亏）。
   - `coverage === 'partial'`：市值一格改为两行，显式拆开：
     ```
     市值 $15,500.00
     其中已计成本 $11,500.00 · 未计成本 $4,000.00
     ```
     并让「浮盈亏」一格的说明明确写成 `（基于已计成本部分 $11,500.00）`，取代现有的 `· 仅含已知成本部分`。
   - `coverage === 'unavailable'`：维持现状（只显示市值 + 成本未知）。
3. **测试**：partial 场景断言 `costedMarketValue + uncostedMarketValue === marketValue`，且 `pnl === costedMarketValue - costBasis`；渲染断言出现「其中已计成本」与「未计成本」两个数字。

提交：`fix: reconcile family pnl card when cost coverage is partial`

### 问题 B（中）：成本不完整且**盈利**时，止盈阶梯照常高亮档位，无任何限定

**位置**：`ConditionLookup.tsx` 的 `SellWindow`：

```ts
const hasKnownLoss = pnl.pnlPct !== null && pnl.pnlPct < 0;
const isPartialLoss = pnl.coverage === 'partial' && hasKnownLoss;   // 只覆盖亏损
const activeStep = !hasKnownLoss && pnl.pnlPct !== null
  ? steps.find(...) : undefined;                                     // 盈利时照常高亮
```

`isPartialLoss` 只处理"成本不完整 + 亏损"。当"成本不完整 + 盈利"时，`activeStep` 会把某一档（例如「盈利 7–10%：减总仓 3%」）高亮成绿色权威结论，`belowFirst` 也会给出精确的"还差 X 点"，而这些全部建立在**不完整的成本**之上。

亏损时要求"不要下断言"，盈利时同样是不完整数据，不能反过来当权威 —— 这是同一条原则的两面。

**修法**：

1. 新增 `isPartialGain = pnl.coverage === 'partial' && pnl.pnlPct !== null && pnl.pnlPct >= 0`。
2. `isPartialGain` 为真时：
   - 档位仍然可以高亮（保留参考价值），但**必须**在阶梯上方显示琥珀色限定语：
     > 该档位基于已计成本部分（另有 N 个持仓成本未知），实际盈利可能不同；减仓比例请以券商实际成本为准。
   - `belowFirst` 的"还差 X 点"在 partial 时同样附加"（基于已计成本部分）"。
3. `coverage === 'complete'` 时行为完全不变。
4. **测试**：partial + 盈利 25% → 档位高亮**且**出现限定语；complete + 盈利 25% → 档位高亮且**无**限定语（防止回归）；partial + 亏损 → 维持 V11 已有的琥珀提示。

提交：`fix: qualify profit-taking tier when cost coverage is partial`

### 问题 C（轻）：未知成本清单重复，且文案对非期权持仓不准确

**位置**：`familyPnl.ts` 的 `unknownCostHoldings.push(...)` 与 `ConditionLookup.tsx` 的提示文案。

1. 同一标的多张期权分属不同券商时，清单会出现重复项：`NVDA（期权）、NVDA（期权）`。
2. 提示文案无条件写「期权成本需用「补充期权详情」导入」；若缺成本的是**股票**，这句话是错的。

**修法**：

1. `familyPnl.ts`：`unknownCostHoldings` 去重（同名同类型合并，多条时带计数，如 `NVDA（期权 ×2）`）。计数取该族内同名同类型的未计成本持仓条数。
2. `ConditionLookup.tsx`：提示语按清单内容分支 —— 含期权时才出现「期权成本需用『补充期权详情』导入」；纯非期权时改为「请在持仓表补填买入价」；两者都有时都写。
3. **测试**：两张同族期权 → 清单为单条 `NVDA（期权 ×2）`；未知成本仅为股票 → 文案不含"补充期权详情"字样。

提交：`fix: dedupe unknown-cost list and match wording to holding type`
